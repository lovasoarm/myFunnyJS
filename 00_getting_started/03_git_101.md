# 03 : Git : 12 commandes pour ne pas perdre ton code
Temps de lecture ~5 min

Pas un cours Git. Le minimum pour survivre au premier mini-projet sans pleurer.

## Le cycle de base

```
git init          # nouveau dépôt
git status         # où j'en suis
git add fichier       # préparer un fichier
git add .          # préparer tout
git commit -m "message"   # figer un snapshot
git log --oneline      # historique court
```

## Travailler avec un remote

```
git clone URL        # cloner
git pull          # tirer les changements
git push          # envoyer les tiens
```

## Branches (le vrai pouvoir)

```
git branch         # lister
git checkout -b feature/x  # créer et basculer
git checkout main      # revenir
git merge feature/x     # fusionner
```

## Règles d'or

- Un commit = une intention. Pas "wip fixes".
- `main` ne casse jamais. Tu bosses en branche.
- Avant de push : `git status` + `git diff`. Toujours.
- Jamais de secret dans un commit. Le `.gitignore` d'abord.

## Piège

`git push --force` sur `main` partagé = mort sociale. Utilise `--force-with-lease` si vraiment nécessaire, jamais sur main.

## Mission

Init un repo dans `/tmp/git-drill`. Trois commits. Une branche. Un merge. Sans copier-coller.
