# GRIMOIRE DU FP : LE LEXIQUE FONCTIONNEL SANS LES MATHS INUTILES

---

| Terme | Définition | Code | Analogies |
|-------|------------|------|-----------|
| **Fonction pure** | Même input → même output. Zéro effet de bord. La fonction ne touche rien en dehors d'elle-même. | `const score = (buts, passes) => buts * 0.5 + passes * 0.3` | Rasengan de Naruto : même chakra en entrée, même puissance en sortie, à chaque fois / Recette de Breaking Bad : mêmes saiyans chimiques, même qualité, sans surprise |
| **Effet de bord** | Toute action qu'une fonction fait en dehors de son scope : modifier une variable globale, écrire en DB, logger, appeler une API. | `function impure(arr) { arr.push(1) }` : `push` est l'effet de bord | Rick Grimes qui modifie l'inventaire du camp sans le dire à personne / Walter White qui change la formule en douce sans mettre à jour le registre |
| **Immutabilité** | Ne jamais modifier un objet existant. Créer un nouveau à la place. L'original est toujours intact. | `const nouveau = { ...ancien, score: 99 }` | L'armure de Leon : on ne la répare pas, on en forge une nouvelle / Un fichier git : chaque commit est un snapshot, jamais une modification de l'historique |
| **`pipe`** | Applique des fonctions en séquence de gauche à droite. La sortie de chaque fonction est l'entrée de la suivante. | `const pipe = (...fns) => x => fns.reduce((v, f) => f(v), x)` | Le pipeline de chakra dans Naruto : chaque transformation s'enchaîne dans l'ordre / La chaîne de distribution de Walter : chaque étape reçoit le saiyan de la précédente |
| **`compose`** | Même chose que `pipe` mais de droite à gauche. Ordre mathématique. | `const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x)` | Lire un combo de jutsu à l'envers pour comprendre quelle technique s'est appliquée en premier / Décoder le plan de Michael Scofield dans l'ordre inverse pour voir comment c'était prévu |
| **Currying** | Transformer `f(a, b, c)` en `f(a)(b)(c)`. Chaque argument retourne une fonction qui attend le suivant. | `const add = a => b => a + b` : `add(10)(5) === 15` | Sasuke qui active ses sharingan niveau par niveau : un niveau = un argument / Michael Scofield qui révèle son plan étape par étape, jamais tout d'un coup |
| **Application partielle** | Fixer certains arguments d'une fonction maintenant, retourner une fonction qui attend le reste. Pas forcément un par un. | `const double = partial(multiplier, 2)` : `double(50) === 100` | Configurer une armure Garo avant la mission : les paramètres fixes du Chevalier sont pré-chargés, les détails de la mission arrivent après / Pré-remplir une feuille de vote Ballon d'Or avec les coefficients de la saison, le joueur arrive plus tard |
| **HOF (Higher-Order Function)** | Fonction qui prend une autre fonction en argument, ou qui en retourne une. `map`, `filter`, `reduce` sont des HOF. | `const doubler = arr => arr.map(x => x * 2)` : `map` est la HOF | Le Conseil de Surveillance Garo qui envoie des Chevaliers : le Conseil décide la stratégie, les Chevaliers exécutent / Mourinho qui donne des instructions tactiques : lui = HOF, les joueurs = fonctions |
| **Fonction unaire** | Fonction qui prend exactement un argument. Prérequis pour la composition directe dans `pipe`. | `const normaliser = joueur => ({ ...joueur, buts: Number(joueur.buts) })` | Un jutsu avec une seule cible : précis, composable, pas d'ambiguïté / Un seul vote Ballon d'Or par journaliste : un input, un résultat |
| **Transparence référentielle** | Une expression est référentiellement transparente si on peut la remplacer par sa valeur sans changer le comportement du programme. Propriété des fonctions pures. | `score(45, 20)` peut partout être remplacé par `32.5` sans rien casser | Une stat de match vérifiée : peu importe qui recalcule, le xG de Haaland reste 0.72 / Une recette validée de Walter : tu peux la remplacer par le saiyan final, le résultat est identique |
| **Mémoization** | Cache du résultat d'une fonction pure basé sur ses arguments. Même call = résultat stocké, pas recalculé. | `const memo = fn => { const cache = {}; return x => cache[x] ?? (cache[x] = fn(x)) }` | L'algorithme de Dijkstra avec mémo : si on a déjà calculé le chemin vers ce noeud, on le lit depuis le cache / Le rating FIFA qui garde en mémoire le score calculé pour ne pas tout recalculer à chaque ouverture |
| **`tap`** | Fonction qui insère un effet de bord (log, debug) dans un pipeline sans modifier les données. Retourne toujours son input. | `const tap = fn => x => { fn(x); return x }` | Un observateur silencieux dans la salle de titanment Garo : il note ce qui passe sans modifier les ordres / Var (Video Assistant Referee) : regarde le jeu, note, ne modifie pas les actions en cours |
| **Functor** | Un conteneur qui implémente `map`. En JS : les tableaux sont des functors. Un functor permet d'appliquer une transformation à ce qu'il contient sans "sortir" du conteneur. | `[1, 2, 3].map(x => x * 2)` : le tableau reste un tableau | Le chakra de Naruto dans un jutsu : transformé à l'intérieur du sceau sans changer sa nature / Un contrat de joueur : les conditions se modifient mais le document reste un contrat |
| **Monade** | Un functor avec `flatMap` (ou `chain`). Permet d'enchaîner des opérations qui peuvent échouer ou être "dans un contexte". Promise est une monade en JS. | `fetch(url).then(r => r.json()).then(data => data.joueurs)` : chaque `.then` est un `flatMap` | Michael Scofield qui enchaîne les étapes d'évasion : chaque étape dépend de la précédente, une seule échoue et tout s'arrête / Les missions Garo en cascade : chaque Chevalier reçoit la mission du précédent, une défaite stoppe la chaîne |
| **Fermeture (closure)** | → Leçon complète : `01_fundamentals/02_scope/02_closure_trap.md` | `const compteur = () => { let n = 0; return () => ++n }` | : |
| **Réduction (`reduce`)** | Transforme une liste en une valeur unique en appliquant une fonction d'accumulation. Base de nombreux patterns FP. | `const total = [1, 2, 3].reduce((acc, x) => acc + x, 0)` | Compter les buts de toute une saison : chaque match ajoute sa valeur à l'accumulateur / T-Bag en prison : il accumule des dettes sur chaque prisonnier, valeur finale = total qu'il peut récupérer |
