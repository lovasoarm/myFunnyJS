# TDD JOURNAL : LEGACY TAKEOVER

Temps de lecture ~2 min


Journal de développement piloté par les tests. Une entrée par cycle RED -> GREEN -> REFACTOR. Sois honnête : ce journal prouve ta démarche, pas ta perfection.

## Modèle d'entrée

```
### Cycle N : <ce que je veux prouver>
RED   : le test que j'écris et pourquoi il échoue au départ.
GREEN  : le minimum de code pour le faire passer.
REFACTOR: ce que je nettoie sans casser le vert.
DOUTE  : ce dont je ne suis pas sûr, à revalider plus tard.
```

## Règle CrazyDevs

Si tu n'as pas vu le test ÉCHOUER en rouge avant de le faire passer, tu ne fais pas du TDD, tu fais de la déco. Comme Naruto qui prétend maîtriser une technique sans jamais l'avoir ratée : personne n'y croit.
