# GRIMOIRE API CRAFT

| Terme | Définition | Code | Analogies |
|-------|-----------|------|-----------|
| REST | Architecture d'API basée sur des conventions HTTP : ressources nommées en URI, verbes HTTP pour les opérations, stateless. | `GET /players/7` `DELETE /players/7` | le cahier de règles de l'arbitre : tout le monde joue selon les mêmes conventions / le plan de Fox River : chaque couloir a un nom, chaque accès un code |
| Middleware | Fonction qui s'intercale entre la réception d'une requête et l'envoi de la réponse. Reçoit `(req, res, next)` et peut modifier les deux ou court-circuiter la chaîne. | `app.use((req, res, next) => { req.ts = Date.now(); next() })` | les gardes de Garo qui inspectent chaque visiteur avant de les laisser entrer / le filtre anti-Horror : chaque détection passe par la même vérification |
| Router | Sous-routeur Express qui regroupe les routes d'une ressource. Monté sur un préfixe d'URL dans l'app principale. | `const r = Router(); app.use('/players', r)` | le vestiaire de chaque équipe : le couloir principal (app) dispatche vers chaque vestiaire (router) / les cellules de Fox River : chaque bloc géré par son propre gardien |
| Status code | Code numérique HTTP décrivant le résultat de la requête. `2xx` succès, `4xx` erreur client, `5xx` erreur serveur. | `res.status(201).json(data)` `res.status(404).json({error})` | le tableau de score : dit si t'as gagné, perdu, ou si le match a été annulé / les signaux de feu de Walter White : vert = livraison ok, rouge = problème |
| 201 Created | Status code renvoyé après une création réussie (`POST`). Accompagné du header `Location` pointant vers la nouvelle ressource. | `res.status(201).set('Location', '/players/7').json(player)` | l'acte de naissance d'un joueur : confirme la création et indique où le trouver / le certificat de recrutement de l'Armée d'Exploration : "t'es officiellement enrôlé, voici ton dossier" |
| 204 No Content | Status code renvoyé après une suppression ou une action sans payload de retour. | `res.status(204).send()` | le silence après que Rick détruit un zombie : l'action est faite, rien à ajouter / la fin d'une patrouille Garo : mission accomplie, pas de rapport à faire |
| 400 Bad Request | La requête est malformée ou les données sont invalides. Le client doit la corriger avant de réessayer. | `res.status(400).json({ error: { code: 'VALIDATION_ERROR' } })` | T-Bag qui essaie d'entrer avec un badge mal rempli : le système refuse, c'est sa faute / un joueur qui fait une faute de règle : c'est lui le problème, pas l'arbitre |
| 401 Unauthorized | L'identité du client n'est pas établie. Token absent, expiré, ou invalide. | `res.status(401).json({ error: { code: 'UNAUTHORIZED' } })` | l'armure de Léo qui expire : tu n'es plus reconnu comme Chevalier / Michael Scofield sans badge : présent, mais non identifié |
| 403 Forbidden | L'identité est établie mais les permissions sont insuffisantes. | `res.status(403).json({ error: { code: 'FORBIDDEN' } })` | T-Bag authentifié mais pas autorisé dans le bureau du directeur / un joueur de réserve identifié mais pas autorisé à jouer en Champions League |
| 409 Conflict | La requête est valide mais entre en conflit avec l'état actuel (doublon, version outdated, stock insuffisant). | `res.status(409).json({ error: { code: 'CONFLICT' } })` | deux joueurs qui réclament le même numéro de maillot : requête légitime, conflit d'état / l'inventaire de Rick qui passe à zéro : opération valide mais stock insuffisant |
| 422 Unprocessable | Les données sont bien formées (JSON valide) mais sémantiquement incorrectes. | `res.status(422).json({ error: { code: 'UNPROCESSABLE' } })` | un formulaire bien rempli mais avec une date de naissance dans le futur : syntaxe ok, sens non / une ordre_mission de livraison avec une adresse qui n'existe pas |
| JWT | JSON Web Token : format de token signé (header.payload.signature). Signé, pas chiffré. Le payload est lisible mais non modifiable sans invalider la signature. | `jwt.sign({ sub: '7' }, secret, { expiresIn: '1h' })` | le laissez-passer de l'Armée d'Exploration : tout le monde peut le lire, personne ne peut le falsifier / le tatouage de Michael Scofield : visible, mais contrefaire la signature est impossible |
| Access token | Token JWT de courte durée (15min à 1h) envoyé dans le header Authorization. Utilisé pour authentifier chaque requête. | `Authorization: Bearer eyJ...` | le ticket de match valable une heure : après, tu dois en prendre un autre / l'armure de Léo : puissante mais avec un compteur de 99.9 secondes |
| Refresh token | Token JWT de longue durée (7-30 jours) stocké en httpOnly cookie. Permet de générer un nouveau access token sans se reconnecter. | `res.cookie('refreshToken', token, { httpOnly: true })` | la carte de saison : dure plus longtemps, permet de recharger le ticket quotidien / le pass permanent de Fox River : t'as pas besoin de te ré-identifier tous les jours |
| httpOnly cookie | Cookie inaccessible via JavaScript (`document.cookie`). Protège contre le vol de token par XSS. | `{ httpOnly: true, secure: true, sameSite: 'strict' }` | le coffre-fort sous le plancher : le visitor peut pas y accéder même s'il fouille la maison / la salle sécurisée de Fox River : identité connue mais accès physique impossible |
| HMAC-SHA256 | Algorithme de signature utilisé par JWT (HS256) : hash du contenu + secret. Modification du payload = signature invalide. | `jwt.sign(payload, secret) // HS256 par défaut` | le sceau de cire d'une lettre royale : si quelqu'un brise le sceau et le recolle, c'est visible / la signature du coach sur les tactiques : toute modification invalide le document |
| AppError | Classe d'erreur personnalisée avec `statusCode` et `code` machine. Distingue les erreurs métier attendues des bugs inattendus. | `class NotFoundError extends AppError { constructor(id) { super('introuvable', 404, 'NOT_FOUND') } }` | l'alerte de niveau dans l'Armée d'Exploration : chaque type de menace a son code, sa réponse calibrée / le signal d'alarme de Fox River : pas la même alarme pour une évasion et une bagarre |
| asyncHandler | Wrapper qui catch les erreurs async et les passe à `next()`. Évite le try/catch répété sur chaque handler. | `const wrap = fn => (req, res, next) => Promise.resolve(fn(req, res, next)).catch(next)` | le filet de sécurité sous un acrobate : il ne change pas le numéro, il intercepte les chutes / le garde-fou de la mine de Walter White : capture ce qui tombe sans interrompre la production |
| OpenAPI Specification | Standard YAML/JSON pour décrire une API REST : endpoints, paramètres, schémas, codes d'erreur. Lisible par les humains et les machines. | `openapi: 3.1.0\npaths:\n  /players:\n    get:` | le plan d'architecte du stade : tout ce que l'API promet, mis sur papier avant même de construire / la carte du tatouage de Scofield : chaque couloir documenté avant l'exécution |
| Swagger UI | Interface web générée depuis une spec OpenAPI. Permet de lire la doc et de tester les endpoints en direct. | `app.use('/docs', swaggerUi.serve, swaggerUi.setup(spec))` | le panneau d'affichage du stade : tout ce qui se passe à l'intérieur, lisible depuis l'extérieur / la table de situation du Conseil des Chevaliers : vue complète de toutes les missions en cours |
| $ref | Référence réutilisable dans une spec OpenAPI. Évite de dupliquer les schémas sur plusieurs endpoints. | `$ref: '#/components/schemas/Player'` | le maillot numéroté : pas besoin de réécrire le nom du joueur partout, le numéro suffit / le code de cellule de Fox River : une référence unique, partagée dans tout le plan |
| Breaking change | Modification d'une API qui casse la compatibilité avec les clients existants. Nécessite une nouvelle version. | renommer `player_id` en `id`, changer type string → number | changer les règles du jeu en cours de match : les joueurs qui connaissaient les anciennes règles sont perdus / modifier les plans de Scofield après impression : tout le monde a la mauvaise version |
| Non-breaking change | Modification d'une API qui n'affecte pas les clients existants. Peut être déployée sans créer de nouvelle version. | ajouter le champ optionnel `assists`, ajouter un endpoint | ajouter une option au menu : les clients qui commandaient pareil peuvent continuer / ajouter un couloir au plan de Scofield sans modifier les couloirs existants |
| URL versioning | Stratégie de versioning qui inclut la version dans l'URL (`/v1/players`, `/v2/players`). | `app.use('/v1/players', v1Router)` `app.use('/v2/players', v2Router)` | les générations de Ballon d'Or : la cérémonie 2023 et la cérémonie 2024 coexistent sans confusion / v1 et v2 des plans de Scofield : l'ancienne version archive, la nouvelle version active |
| Sunset header | Header HTTP standard qui indique la date à laquelle un endpoint sera retiré. | `res.set('Sunset', 'Sat, 31 Dec 2026 23:59:59 GMT')` | la date de fin de contrat d'un joueur : tout le monde sait qu'il part, avec combien de temps pour s'organiser / la date d'exécution dans Prison Break : annoncée, inéluctable, mais il reste du temps |
| Deprecation header | Header HTTP standard qui signale qu'un endpoint est déprécié. | `res.set('Deprecation', 'version="v1"')` | le brassard noir d'un joueur en fin de carrière : encore là, mais son temps est compté / le tatouage de Scofield qui s'efface : le plan existe encore, mais bientôt inutilisable |
| GraphQL | Langage de requête pour API. Le client décrit exactement les données qu'il veut. Le serveur répond exactement ça. | `query { player(id: "7") { name goals } }` | le buffet à volonté vs le menu imposé : en REST tu prends ce qu'on te sert, en GraphQL tu choisis exactement ce que tu veux / Naruto qui combine ses techniques exactement comme il veut : pas de jutsu imposé |
| Resolver | Fonction GraphQL qui retourne la valeur d'un champ du schema. Appelée pour chaque champ demandé dans la query. | `Query: { player: (_, { id }) => players.find(p => p.id === id) }` | chaque joueur de l'équipe a sa mission : le resolver `Player.team` est le spécialiste du champ `team`, il fait ça et rien d'autre / chaque cellule de Fox River a son responsable |
| N+1 problem | Bug de performance GraphQL : pour résoudre une liste de N objets avec une relation, le resolver est appelé N fois → N requêtes DB au lieu d'une. | `// 100 players --> 100 appels DB pour Player.team` | envoyer un coursier séparé pour chaque lettre au lieu d'un seul facteur qui fait la tournée / interroger chaque prisonnier individuellement au lieu d'une seule réunion générale |
| DataLoader | Utilitaire qui batch les appels répétés de resolvers GraphQL en une seule requête DB. Résout le problème N+1. | `new DataLoader(ids => db.getPlayersByIds(ids))` | le facteur qui collecte toutes les lettres du quartier avant de partir faire la tournée / Walter White qui livre toutes les ordres_mission d'une zone en un seul voyage |
| Stateless | Chaque requête HTTP porte toutes les informations nécessaires. Le serveur ne garde pas de mémoire entre requêtes. | chaque requête avec `Authorization: Bearer token` | un serveur de restaurant qui ne se souvient de rien : chaque ordre_mission doit être complète / Fox River sans base de données : chaque garde doit avoir son badge sur lui à chaque fois |
| Rate limiting | Limitation du nombre de requêtes autorisées par unité de temps par client. Protège contre le brute force et les abus. | `app.use(rateLimit({ windowMs: 60000, max: 100 }))` | le filtre anti-spam des votes Ballon d'Or : un journaliste = un vote par heure / le quota de passage de la porte de Fox River : pas plus de 10 entrées par heure par badge |
| CORS | Cross-Origin Resource Sharing : mécanisme qui permet ou interdit les requêtes d'une origine différente. Configuré via des headers HTTP. | `app.use(cors({ origin: 'https://myfunny.dev' }))` | la liste des délégations étrangères autorisées à entrer au Conseil des Chevaliers / les clubs autorisés à recruter des joueurs du championnat : tout le monde ne peut pas |
| Idempotence | Propriété d'une opération : l'appeler une ou cent fois jutsu le même résultat. `GET`, `PUT`, `DELETE` sont idempotents. `POST` ne l'est pas. | `PUT /players/7 { goals: 30 } // même résultat à chaque appel` | appuyer 10 fois sur le bouton d'arrêt d'une machine : ça s'arrête une fois et reste arrêtée / Walter White qui fixe le prix à 10k : peu importe combien de fois tu demandes, c'est toujours 10k |
| Content negotiation | Mécanisme HTTP où le client signale le format qu'il peut accepter via le header `Accept` et le serveur répond dans ce format. | `Accept: application/json` `Content-Type: application/json` | ordre_mission en français dans un restaurant multilingue : le serveur s'adapte à la langue du client / Scofield qui demande le plan en version imprimée ou numérique : le serveur livre dans le format demandé |
