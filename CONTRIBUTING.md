## Bienvenue dans le labo

Si tu lis ça, c’est que tu veux contribuer à MyFunnyJS.  
Très bon choix.

Ici on ne code pas pour faire joli.  
On code pour comprendre.  
On code pour devenir solide techniquement.

---

## Règle numéro 1 : comprendre avant de coder

Chaque contribution doit :

- Expliquer un concept clairement
- Montrer le problème
- Faire réfléchir
- Forcer à écrire du vrai code

Pas de copier-coller vide de sens.  
Pas de code magique sans explication.

Un fichier = un concept précis.

---

## Structure obligatoire d’un fichier d’exercice

Chaque fichier doit suivre cette logique :

### 1. Une leçon en commentaire en haut du fichier

- Mots simples
- Phrases courtes
- Logique expliquée
- Pourquoi c’est important dans la vraie vie
- À quoi ça sert en ingénierie

Si quelqu’un ouvre le fichier seul, il doit tout comprendre.

### 2. Le challenge étape par étape

Des instructions claires.  
Progressives.  
Logiques.

### 3. Code de départ

Base minimale.  
Pas de solution cachée.

### 4. Zone "Votre code"

L’espace où la personne doit réfléchir et coder.

---

## Style de code

On reste propre.

- Variables avec des noms clairs
- Pas de fonctions monstrueuses inutiles
- Indentation propre
- Code lisible avant tout

Si ton code est difficile à lire, il est mal pensé.

## Esprit du projet

MyFunnyJS est sérieux.  
Mais l’ambiance est fun.

On peut utiliser :

- Zombies
- Pirates
- Robots
- Aliens
- Laboratoires magiques
- Ou n’importe quel univers créatif

Mais le fond doit rester solide.

Le fun ne remplace jamais la rigueur.

---

## Utiliser l’IA intelligemment

Tu peux utiliser une IA.

Mais :

- Ne copie jamais sans comprendre
- Analyse ce qu’elle propose
- Refactore
- Vérifie la complexité
- Vérifie la sécurité

L’IA peut générer du code.  
Toi tu dois le comprendre.
