# GRIMOIRE DES EDGE CASES : JS QUI SE REBELLE

Le manuel de survie des comportements que JS ne documente pas assez clairement.
Chaque terme ici correspond à un piège réel, un bug possible, ou une décision de conception du moteur.

## ANTI-PATTERNS À BANNIR

```
==  au lieu de ===         -->  coercions non contrôlées
__proto__                  -->  utiliser Object.getPrototypeOf / Object.create
hasOwnProperty direct      -->  utiliser Object.hasOwn
|| pour les défauts numériques -->  utiliser ?? si 0 est une valeur valide
merge() sans sanitization  -->  vecteur de prototype pollution
typeof pour null           -->  typeof null === "object" est un leurre
for...in sans hasOwn       -->  itère sur les propriétés héritées
setTimeout pour "résoudre" une race condition --> déplace le seuil, ne corrige rien
```

## CHECKS RAPIDES EN PROD

```js
// Vérifier un nombre valide (pas NaN, pas Infinity)
Number.isFinite(val) && !Number.isNaN(val)

// Vérifier null ET undefined d'un coup
val == null              // true si null ou undefined:le seul bon usage de ==

// Défaut sûr qui respecte 0
const result = val ?? "défaut"

// Itérer sur les propriétés propres uniquement
Object.entries(obj).forEach(([k, v]) => ...)

// Vérifier une propriété propre sans risque
Object.hasOwn(obj, "clé")

// Comparer des floats
Math.abs(a - b) < Number.EPSILON

// Détecter prototype pollution dans un merge
if (key === "__proto__" || key === "constructor" || key === "prototype") continue
```
